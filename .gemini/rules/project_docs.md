# プロジェクト固有開発・設計規約（ロケットアナライザー）

本プロジェクトにおいて、AIエージェントはグローバル運用規約に加え、以下の現場固有要件を厳守してください。

1. **技術資料の具象マッピング（Single Source of Truth）**:
   - 参照優先度: `docs/README.md`（全体概要）→ `docs/01_requirements_definition.md`（要件）→ `docs/specs/`（設計）→ `docs/guides/`（運用）。
   - グローバル第8条の「進捗表」対象ファイルは `docs/guides/02_implementation_status.md` とし、タスク完了時の更新はこれに限定する（`docs/specs/` の同期は仕様変更時のみ）。

2. **iPhone PWA / モバイル操作性基準（配達現場向け絶対要件）**:
   - **フォーム自動ズーム防止**: iOS Safariのフォーカス時自動ズームを防ぐため、すべての input / select / textarea のフォントサイズは最小 16px（Tailwind: `text-base`）以上を必須とする。
   - **画面高とダブルタップ制御**: アドレスバー伸縮によるボタン隠れを防ぐため全画面配置は `100dvh` を基準とし、連打操作時の画面誤拡大を防ぐためボタン・タップ要素には `touch-action: manipulation` を適用する。
   - **セーフエリア & タップ領域**: 下部固定ナビや操作ボタンは `env(safe-area-inset-bottom)` を必ず確保し、片手操作のため最小 44×44px のタップ領域を維持する。
   - **PWAチャンクエラー耐性**: デプロイ後の旧JSキャッシュ起因（ChunkLoadError）による画面ホワイトアウトを防ぐため、エラー境界での自動リロードまたは再同期導線を維持する。
   - **UI・デザイン統一**: アイコンは導入済みの `lucide-react`、スタイリングは既存の Tailwind CSS を遵守し、無断での外部UIライブラリ追加を禁止する。

3. **オフラインファースト ＆ データ同期設計（現場データ保全）**:
   - 電波不安定環境（地下・EV内）を前提とし、入力データは即座にLocalStorageへ先行保存（UUID採番）してUIを即時更新。通信復帰時にSupabaseへバックグラウンド同期（Sync Queue）する。
   - 通信断時やAPIエラー時に未捕捉例外でアプリを停止させない例外ハンドリングを徹底する。
   - データ構造変更時は、端末キャッシュ残存時のクラッシュを防ぐデフォルト値マージを必須とする。
   - Supabase無料枠（Egress 5GB）保護のため、日報等のデータ取得時は全件フェッチを禁止し、期間絞り込みまたは件数制限（`limit`）を必須とする。
   - **端末ストレージ（5MB）保護**: LocalStorageの容量枯渇（QuotaExceededError）を防ぐため、同期完了済みSync Queueは即時削除し、ローカル残存データは直近分のみ自動パージする設計とする。
   - 通信復帰時のSync Queue再同期は、端末負荷と通信集中を防ぐため指数バックオフ（または一定間隔）を適用し、過剰なリトライ連打を禁止する。

4. **プライバシー & 認証境界（Supabase RLS）**:
   - 配達員の個人情報・日報データを保護するため、匿名利用時であっても端末UUIDまたはSupabase匿名認証（Anonymous Auth）をキーとしたRLS分離を必須とする（`USING (true)` による全開放は厳禁）。

5. **完全0円 & 省リソース運用の徹底（通信・バッテリー・API保護）**:
   - 天気情報等は完全無料（APIキー不要・クレカ不要）の Open-Meteo を最優先とし、地図・住所検索（Google Maps等）の従量課金API利用時はローカルキャッシュおよび無料代替（国土地理院APIやOpenStreetMap等）へのフォールバック導線を常設する。
   - **バッテリー保護**: 高精度GPSの常時監視（watchPosition）を禁止し、記録時のシングルショット取得（getCurrentPosition）を徹底する。
   - **通信軽量化**: 現場の低速通信に配慮し、巨大ライブラリ（Recharts等）は遅延読み込み（React.lazy）を適用して初期バンドル通信量を極小化する。
   - **住所検索の課金圧縮**: 住所・建物名検索（Places API等）利用時は、1文字ごとの個別課金を防ぐセッショントークン（Session Token）適用を必須とする。
