# プロジェクト固有開発・設計規約（ロケットアナライザー）

本プロジェクトにおいて、AIエージェントはグローバル運用規約に加え、以下の現場固有要件を厳守してください。

1. **技術資料の具象マッピング（Single Source of Truth）**:
   - 参照優先度: `docs/README.md`（全体概要）→ `docs/01_requirements_definition.md`（要件）→ `docs/specs/`（設計）→ `docs/guides/`（運用）。
   - グローバル第8条の「進捗表」対象ファイルは `docs/guides/02_implementation_status.md` とし、タスク完了時の更新はこれに限定する（`docs/specs/` の同期は仕様変更時のみ）。

2. **iPhone PWA / モバイル操作性基準（配達現場向け絶対要件）**:
   - **フォーム自動ズーム防止**: iOS Safariのフォーカス時自動ズームを防ぐため、すべての input / select / textarea のフォントサイズは最小 16px（Tailwind: `text-base`）以上を必須とする。
   - **画面高・バウンス・連打制御**: 全画面配置は `100dvh` を基準とし、最上位画面での意図しない引っ張りリロードを防ぐため `overscroll-behavior-y: none` を適用する（日報履歴等の内部スクロール領域の正常スクロールを阻害しない設計とする）。連打誤拡大防止のため操作要素には `touch-action: manipulation` を適用する。
   - **セーフエリア & タップ領域**: 下部ナビ・操作ボタンは `env(safe-area-inset-bottom)` を確保し、片手操作のため最小 44×44px のタップ領域を維持する。
   - **配達中スリープ防止 & 長時間稼働耐性**: 配達稼働中の画面消灯を防ぐScreen Wake Lock制御（非対応環境は安全に無視）、およびデプロイ時キャッシュ事故を防ぐChunkLoadError境界（自動再読込）を常設する。また、数時間の連続起動によるWebKitメモリクラッシュ（タブ突然死）を防ぐため、`useEffect` 内でのブラウザAPIリソース購読（タイマー `clearInterval`、イベントリスナー `removeEventListener`、Wake Lock解放）の解除処理を徹底する。なお、画面遷移やアンマウントに伴い、ユーザー入力中の未登録フォームデータ・下書き・未同期キューを破棄・リセットすることは厳禁とし、入力データは確実に保護・維持する設計とする（LocalStorage書き込み時の `QuotaExceededError` やパース異常時もアプリクラッシュを遮断し、インメモリ退避・エラー境界で保護する）。
   - **UI・デザイン統一**: アイコンは `lucide-react`、スタイルは Tailwind CSS を厳守し、無断の外部UIライブラリ追加を禁止する。

3. **オフラインファースト ＆ データ同期設計（現場データ保全）**:
   - 電波不安定環境を前提とし、入力データは即座にLocalStorageへ先行保存（ブラウザ標準 `crypto.randomUUID()` で採番）してUIを即時反映。通信復帰時にSupabaseへバックグラウンド同期（Sync Queue）する。
   - **ストレージ名前空間 & 拡張性**: LocalStorageキーは他アプリとの衝突を防ぐためプレフィックス `rocket_analyzer_` を必須とし、端末識別（`..._device_id`）と未同期キュー（`..._sync_queue`）を共通基盤とする。日報（`..._delivery_logs`）に加え、将来の拡張データ（メモピン、オファー履歴、設定等）も同プレフィックス配下で柔軟なキー追加を認める。
   - **冪等性 & 競合解消**: 再送時の二重計上を防ぐため同期はUUID主キーによる `upsert` を前提とし、競合時は現場入力（更新日時タイムスタンプ準拠のLast-Write-Wins）を優先する。
   - **データ構造・DB後方互換性**: 端末キャッシュ残存時のクラッシュを防ぐLocalStorageのデフォルト値マージを必須とする。また、Supabase側のテーブル定義変更時も、新カラムにはNULL許容またはDEFAULT値設定を必須とし、既存日報の同期upsertを破壊しない後方互換性を維持する。
   - **リソース・ストレージ保護**: Supabase無料枠（Egress 5GB）保護のため全件取得を禁止し（期間絞り込み/`limit`必須）、常時WebSocket接続（Supabase Realtime）による無駄な通信・バッテリー浪費を防止する（画面表示時・Sync完了時の一発オンデマンドフェッチを徹底）。LocalStorage枯渇（5MB制限）を防ぐため未同期キューは同期完了時に即時削除し、同期済み過去データは直近30日（または100件）を上限保持とし、超過分から古い順に安全パージする（未同期データは同期完了まで絶対保護）。
   - 通信復帰時のSync Queue再同期は、端末負荷と通信集中を防ぐため指数バックオフ（または一定間隔）を適用し、過剰なリトライ連打を禁止する。また、通信復帰イベントや連打による多重送信（無駄なEgress消費）を防ぐため、同期処理の単一実行保証（実行中フラグ等の排他制御）を徹底する。なお、APIバリデーションエラー等で恒久的に失敗する不正データ（ポイズンピル）によるキュー閉塞を防ぐため、上限リトライ（最大3回）超過時はエラー隔離退避（Dead Letter）して後続同期を阻害しない設計とする。オフラインや同期保留中もUI上に未同期インジケーターを表示し、配達員が記録完了状態を視覚的に把握できる縮退運転UXを維持する。

4. **プライバシー & 認証境界（Supabase RLS & 環境変数保護）**:
   - 配達員の個人情報・日報データを保護するため、匿名利用時は端末UUIDまたはSupabase匿名認証（Anonymous Auth）をキーとしたRLS分離を必須とする（`USING (true)` による全開放は厳禁）。なお、将来的なアカウント本認証（メール/OAuth）導入時は `auth.uid()` への移行・統合を妨げない設計とする。
   - **環境変数 & オリジン保護（グローバル第11条具体化）**: Supabaseの管理者鍵（`service_role`）をフロント環境変数に含めることを厳禁とし、公開キー（`VITE_SUPABASE_ANON_KEY`, `VITE_GOOGLE_MAPS_API_KEY` 等）は `.env.example` に安全なテンプレートを同期維持する。またGoogle Mapsキーは本番URL（Vercel）およびローカル開発に限定したHTTPリファラー制限を必須とする。

5. **完全0円 & 省リソース運用の徹底（通信・バッテリー・API保護）**:
   - 天気情報等は完全無料（APIキー・クレカ不要）の Open-Meteo を最優先とし、地図・住所検索の従量課金API利用時はローカルキャッシュおよび無料代替（国土地理院APIやOpenStreetMap等）へのフォールバック導線を常設する。
   - **地図API課金・多重ロード封殺**: Google Maps JavaScript API利用時は、Reactの再レンダリングやタブ切替によるスクリプト多重読み込み・Mapインスタンス多重生成（Map Loads課金事故）を防止するため、スクリプトの単一ロード管理およびコンポーネントアンマウント時のクリーンアップ・インスタンス再利用を徹底する。
   - **住所検索の課金圧縮**: 住所・建物名検索（Places API等）利用時は、1文字ごとの個別課金を防ぐセッショントークン（Session Token）適用を必須とする。
   - **バッテリー保護 & GPS耐障害性**: 高精度GPSの常時監視（watchPosition）を禁止し、記録時のシングルショット（getCurrentPosition、適切なtimeout・maximumAge指定）を徹底。取得失敗時（地下・屋内等）でもブロックせず手動入力可能なフォールバックを常設する。
   - **通信軽量化**: 現場の低速通信に配慮し、巨大ライブラリ（Recharts等）は遅延読み込み（React.lazy）を適用して初期バンドル通信量を極小化する。

6. **自己検証コマンド ＆ テストスコープ規約（グローバル第5条準拠）**:
   - **コマンド実行基準**: 自己検証は `package.json` の `scripts` に定義されたコマンドに厳格準拠する。未定義のコマンド（現時点で未導入の `npm test` 等）の推測実行は厳禁とし、現状は `npm run build`（Vite production build）のみを実行する。
   - **将来のテストスコープ**: 将来的に単体テスト環境を導入する場合（Sync Queue本格化やフェーズ2計算ロジック拡張時）は、Viteと親和性の高い `vitest` を採用し、対象はUI描画ではなく「純粋ロジック層（時給・経費・オファー判定計算、Sync Queueの冪等性・指数バックオフ）」に限定する（`npm test` スクリプト定義後は、ビルド前の自動実行を必須とする）。
