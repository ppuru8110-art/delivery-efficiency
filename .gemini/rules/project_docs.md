# プロジェクト技術資料管理 & チャット間共有ルール

本プロジェクトにおいて、AIエージェントは知識の風化防止、セッション間引き継ぎ、および品質維持のために以下を順守してください。

1. **技術資料の一括参照（セッション開始時 & 効率的参照の原則）**:
   - 新しいセッション・チャットの開始時や本格的な機能実装・設計タスクの着手時、AIエージェントはプロジェクトルート直下の `docs/` フォルダ配下にある技術資料を確認し、プロジェクトの現状、要件定義、およびロードマップを同期すること。
     - `docs/README.md`
     - `docs/01_requirements_definition.md`
     - `docs/specs/` 配下の各設計仕様書
     - `docs/guides/02_implementation_status.md`（実装進捗状況・チェックリスト）
     - `docs/guides/03_roadmap_and_upcoming.md`（ロードマップ）
   - **効率化・省エネガード**:
     - 単発の質問対応、エラー相談、1〜2行の軽微な修正等では、上記ドキュメントの全走査をスキップして即座に応答すること。
     - 同一セッション内ですでに内容を把握済みの場合は、毎ターン無駄に再読み込み（view_file等）を行わないこと。

2. **ドキュメントの最新化維持義務（Single Source of Truth）**:
   - 新機能の実装、仕様変更、または計画されたタスクの完了時は、コード変更と同一作業内で必ず対応する `docs/` 配下のドキュメント（特に進捗状況 `docs/guides/02_implementation_status.md`）を最新状態に更新・同期すること（※ 仕様に影響しない軽微な微調整やtypo修正等では、ドキュメントの都度更新を強制せず開発スピードを優先する）。

3. **次回への引き継ぎ & 作業終了（デイリークローズ）時の状態維持**:
   - チャット切り替え時や本日の作業終了（シャットダウン）時には、未反映事項を進捗ドキュメント（`docs/guides/02_implementation_status.md` 等）に記録し、GitHubへプッシュした上で、次回再開用の引き継ぎ指示書（Handoff Prompt / `docs/guides/05_handoff_prompt.md` 相当）を提示すること。どのチャット・別端末・別日でも即座に続きから再開できる状態を維持する。

4. **技術資料の隔離保持**:
   - `docs/` ディレクトリ直下およびサブディレクトリには純粋な技術資料（Markdown形式やSQLスキーマ等）のみを保存し、アプリコードや一時ファイル・ビルド成果物を配置しないこと。
