# Git / GitHub 自動運用ルール（完全自動型）

本プロジェクトにおいて、AIエージェントは以下のプロトコルに従い、バージョン管理（Git/GitHub）を自動的に実行します。

## 1. 適用条件の自動判定
- プロジェクトルートに `.git` ディレクトリが存在し、Gitリポジトリとして初期化されていること。
- `git remote` が設定されていること（GitHub等のリモートが存在すること）。
- 上記条件を満たさない場合は、バージョン管理操作をスキップし、必要に応じて初期化を提案する。

## 2. 自動コミット＆プッシュのタイミング
- ユーザーから依頼されたタスク（新機能の実装、不具合修正、リファクタリング、設定変更など）が完了し、動作確認・検証が取れた時点。
- `docs/` 配下の技術資料の同期・最新化（`.gemini/rules/project_docs.md` 準拠）を行った直後。

## 3. 実行手順
AIエージェントはタスク完了時に以下の手順を自律的かつ自動で実行する：

1. **差分確認**:
   - `git status` および必要に応じて `git diff` を確認し、意図しない不要なファイル（一時ファイルや認証情報等）が含まれていないかチェックする。
2. **ステージング & コミット**:
   - 変更内容に応じた適切なプレフィックス（Conventional Commits）と、作業内容の明確な日本語要約を用いてコミットする。
   - **プレフィックス例**:
     - `feat:` 新機能の追加・拡張
     - `fix:` バグや不具合の修正
     - `docs:` ドキュメントのみの変更
     - `style:` コードの動作に影響しない見た目・フォーマットの変更
     - `refactor:` リファクタリング（機能追加やバグ修正を含まないコード改善）
     - `test:` テストコードの追加・修正
     - `chore:` ビルド構成や補助ツールの変更、ルール設定等
3. **リモートへの自動プッシュ**:
   - コミット後、直ちに現在のブランチ（例: `main`）に対して `git push origin <現在のブランチ>` を実行する。
4. **ユーザーへの完了報告**:
   - 変更内容のサマリー、コミットハッシュ、プッシュ完了の旨を報告に含める。
