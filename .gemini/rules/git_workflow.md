# Git / GitHub 自動運用ルール

本プロジェクトにおいて、AIエージェントは以下のプロトコルに従い、バージョン管理（Git/GitHub）を適切かつ安全に自動実行します。

## 1. 適用条件
- プロジェクトルートに `.git` およびリモートリポジトリ（GitHub等）が存在する場合に自動適用する（存在しない場合はスキップ）。

## 2. 作業前の同期
- 新しいタスク着手前やブランチ派生前には、リモートの最新状態（`git pull`）を確認し、ローカルを最新に保つ。

## 3. ブランチ方針
- **通常時**: ブランチを切らずに現在のブランチ（`main`）に直接自動コミット＆プッシュを行い、開発スピードを最優先とする。
- **ブランチ作成の例外**:
  - ユーザーから明示的な指示があった場合
  - プレビュー環境での事前確認（Vercel等のPreview Deployment利用）が必要な場合
  - 失敗リスクが高い大規模な実験・破壊的リファクタリングを行う場合
  ※ 上記例外時は `feature/xxx` や `fix/xxx` などの作業ブランチを最新の `main` から派生して作成する。

## 4. セキュリティ＆安全対策（厳格順守）
- **機密情報の排除**: `.env`、APIキー、トークン、秘密鍵等の機密情報は絶対にコミット・プッシュしない（`.gitignore` の設定確認）。
- **不要ファイルの排除**: ビルド成果物（`dist/`等）、依存パッケージ（`node_modules/`等）、OS一時ファイルはコミットに含めない。
- **破壊的操作の禁止**: `main` ブランチへの強制プッシュ（`git push --force`）や未確認での履歴破棄（`git reset --hard`）は行わない。

## 5. コミット＆プッシュ実行プロトコル
タスク完了・検証直後に以下の手順を実行する：
1. `git status` 等で差分を確認し、意図しない不要ファイルや機密情報が含まれていないかチェックする。
2. 1つのコミットに無関係な変更を混在させず、タスク単位で独立したコミットとする。
3. Conventional Commits形式（`feat:`, `fix:`, `docs:`, `style:`, `refactor:`, `test:`, `chore:` 等）＋明確な日本語要約を用いてコミットする。
4. コミット後、直ちに現在のブランチに対して `git push origin <現在のブランチ>` を自動実行する。
5. ユーザーへコミットハッシュ、コミットメッセージ、プッシュ完了の旨を報告する。

## 6. ブランチのマージ・破棄（作業ブランチ運用時のみ）
- **マージ（採用時）**:
  - ユーザーの確認・承認を得た上で `main` ブランチへマージし、リモートへプッシュする。
  - マージ完了後、役目を終えた作業ブランチ（ローカルおよびリモート）を自動削除してリポジトリをクリーンに保つ。
- **破棄（不採用・やり直し時）**:
  - ユーザーから破棄・やり直しの指示があった場合、未コミットの変更を破棄して安全に `main` へ切り替え、作業ブランチ（ローカルおよびリモート）を完全削除する。
