# 02. UI・画面設計書 (UI & Screen Design)

## 1. 画面構成一覧

本アプリは、iPhone画面下部に常駐する**ボトムナビゲーション**により、画面間をワンタップで切り替える構成です。

| タブ / 画面名 | アイコン | 概要 | ステータス |
| :--- | :--- | :--- | :--- |
| **ダッシュボード** | 📊 `LayoutDashboard` | 時給・単価指標、グラフ、確定申告試算 | **フェーズ1（実装対象）** |
| **日報入力** | 📝 `PlusCircle` | 日々の稼働データ入力フォーム | **フェーズ1（実装対象）** |
| **エリアマップ** | 🗺️ `MapPin` | Google Maps による高効率エリア視覚化 | **フェーズ1（実装対象）** |
| **オファー判定** | ⚡ `Zap` | 案1統合用シミュレーター（1km単価・時給即時計算） | *フェーズ2（枠組み用意）* |
| **攻略メモ** | 📌 `BookMarked` | 案2統合用店舗・マンション注意メモ | *フェーズ3（枠組み用意）* |

## 2. 画面レイアウト詳細

### ① ダッシュボード画面 (`/dashboard`)
iPhoneの上部から縦スクロールで以下のカード群を表示します。

1. **核心メトリクスカード (4列/2列グリッド)**
   - 💰 **平均時給**: `総売上 ÷ 総稼働時間` （例: 2,450 円/h）
   - 📦 **件単価**: `総売上 ÷ 総件数` （例: 680 円/件）
   - 🚗 **km単価**: `総売上 ÷ 総走行距離` （例: 145 円/km）
   - ⏱️ **平均配達時間/件**: `総稼働時間 ÷ 総件数` （例: 18 分/件）
2. **稼ぎ分析グラフカード**
   - 曜日別（月〜日）の平均時給比較棒グラフ (Recharts)
   - 天候別（晴・雨等）の平均時給比較
3. **確定申告・経費試算カード ＆ データ管理**
   - 今月の売上累計 / 今年の売上累計
   - 総走行距離からの概算経費（ガソリン代・車両消耗費の目安計算）
   - **確定申告用 CSV / JSON エクスポートボタン**
   - **誤操作防止（2段階確認モーダル）**: デモデータ投入・全データ初期化を実行する際、ローカル実データや未同期データが存在する場合は「〇件のデータが上書き/消去されます。本当によろしいですか？」と警告する確認モーダルを表示し、誤タップによる即時データ破棄を遮断。
4. **日報履歴一覧 ＆ 編集/削除モーダル**
   - 過去に入力した日報ログの一覧表示および編集・削除アクション

### ② 日報入力画面 (`/entry`)
片手で数分で入力できるシンプルなフォーム。

- **下書き復元バナー**: 未完了の下書きが存在する場合、フォーム最上部に「前回の入力データがあります［復元する］［破棄］」を表示。
- **業務日（稼働日）**: デフォルト本日。深夜（22:00〜翌2:00等）の日またぎ稼働でも稼働開始日を維持・変更可能。
- **プラットフォーム選択**: ［Uber Eats / 出前館 / menu / Wolt / その他］ワンタップ選択チップ。
- **稼働時間**: 開始時刻〜終了時刻（自動で稼働時間を算出）
- **売上金額（円）**: 数値入力（`text-base` 16px以上）
- **配達件数（件）**: 数値入力（`text-base` 16px以上）
- **走行距離（km）**: 数値入力（`text-base` 16px以上）
- **天候選択**: ワンタップボタン［晴れ / 曇り / 雨 / 大雨］＋ **「現在地の天気を自動取得」ボタン（Open-Meteo API連携）**
- **主要エリア**: テキスト入力
- **メモ**: 自由記述（`maxLength={500}`）
- **保存ボタン**: 送信中は非活性化（disabled）。登録成功時に下書きをクリアしてダッシュボードへ自動遷移。

### ③ エリアマップ画面 (`/map`)
- **Google Maps 表示**: ユーザーの稼働実績（日報データ）に基づき、ピンまたはヒートマップを表示。
- APIキー未設定時は、スマートプレースホルダーマップを表示。
- ピンをタップすると、その日の「平均時給」「天候」「売上」がポップアップ表示されます。

### ④ ヘッダー ＆ 縮退運転ステータス (`Header.jsx`)
- **未同期バッジ**: 未同期キューがある場合は雲アイコン＋件数バッジ（例: `☁️ 2`）を表示。
- **オフラインインジケーター**: 電波遮断時（`navigator.onLine === false`）は「ローカル記録中」ステータスを表示し、配達員の安心感を確保。

## 3. レスポンシブ & PWA（iPhone）デザイン要件

- **フォーム自動ズーム防止（iOS Safari必須要件）**: すべての `input`, `select`, `textarea` のフォントサイズは最小 16px（Tailwind CSS の `text-base`）以上を必須とし、入力フォーカス時の画面強制自動ズームおよび操作性崩れを完全に防止。
- **セーフエリア考慮**: iPhoneのノッチ（画面上部）およびホームバー（画面下部）と被らない padding (`env(safe-area-inset-bottom)`) を確保。
- **タッチターゲット**: ボタン類は最低 44×44px 以上のタップしやすいサイズを維持。
- **屋外視認性・高コントラスト基準 (WCAG AA 4.5:1)**: 直射日光下・夜間走行時の安全性を確保するため、薄い文字色（Tailwind: `text-slate-400` / `text-gray-400` 以下）での主要メトリクス表示を禁止し、`text-slate-100` / `text-emerald-400` / `text-amber-400` 等の十分な視認コントラストを担保。
- **ErrorBoundary フォールバック画面**: アプリ全画面白画面クラッシュを遮断し、「画面を再読み込み」ボタンおよび「未同期データをJSON保存（救済）」ボタンを常設。
