## 2. 確定済みのコア検証観点（保持必須）
以下のコア観点を常設の審査基準として維持します：
1. **リソース防護軸（通信・料金・端末リソースの極小化）**:
   - Supabase無料枠（DB 500MB / Egress 5GB）の厳格保護。
   - Google Maps等の外部APIにおける従量課金リスクの完全排除（0円運用維持）。
   - 現場モバイル回線配慮（バンドル軽量化・無駄な通信排除）および端末保護（LocalStorage 5MB・バッテリー・長時間メモリリーク）。
2. **開発拡張性軸（アンチ硬直性・将来フェーズとの調和）**:
   - ガードレールが将来フェーズ（オファー判定、攻略メモピン等）の新データ・新機能追加を阻害しないこと。
   - 将来のアカウント本認証（`auth.uid()`）や外部サービス拡張を自然に受け入れられること。
   - YAGNIを守りつつ、将来の自動テスト（Vitest）導入へ摩擦ゼロで移行できること。
3. **死角・曖昧表現の排除 ＆ 多プロジェクト普遍適合性（SoCの極致）**:
   - 将来の実装AIが誤認・迷走・データロストを起こす「曖昧な表現」や「ガードレールの穴」を完全排除。
   - グローバル規約が他言語・他フレームワークでも完全にノイズなく機能すること。
4. **トークン効率・認知負荷の極限圧縮**:
   - 命令強度を100%維持したまま、重複や冗長な表現を削ぎ落とすこと。
